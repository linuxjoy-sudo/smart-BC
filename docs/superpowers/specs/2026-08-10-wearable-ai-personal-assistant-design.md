# SmartBC：会成长的个人助理 — 设计文档

- 日期：2026-08-10
- 状态：草稿（待用户审阅）
- 定位：消费级穿戴式个人助理的前置软件验证阶段

## 1. 背景与目标

### 1.1 愿景

穿戴式个人助理（后期硬件形态为 AI 吊坠/项链），能够：
- 记忆用户信息（人脉、承诺、偏好、事件）
- 持续收集用户信息（习惯、发生的事情）
- 随时间推移更懂用户（数据积累驱动个性化）
- 主动为用户规划个人事项（前瞻性提醒与安排）

### 1.2 本次验证目标

单人团队 + 有限预算，**先以纯软件 MVP 验证核心需求粘性**，不直接做硬件。

- **产品形态**：桌面版应用（Tauri），用户使用蓝牙耳机或电脑麦克风进行语音输入
- **目标市场**：中国市场（中文优先）
- **成功标准**：小规模留存验证——自己 + 3-5 名种子用户连续使用 2-4 周，每周 ≥3 次主动打开，验证"记忆 + 主动提醒"形成使用习惯

### 1.3 验证后的演进路径

1. 软件 MVP（本次）：桌面版，蓝牙耳机为采集设备
2. 手机端：更贴近随身场景
3. 习惯学习与前瞻规划：需要 2-4 周数据积累后实现
4. 自研硬件：AI 吊坠/项链（ESP32 级 MCU + 麦克风 + BLE），手机/云端为算力中枢

## 2. 产品定位

**一句话定位**：戴上耳机跟它说话，它永远记得你的一切，并在你需要的时候主动提醒你。

**依赖感公式**：FOMO（记得一切）+ 怕忘事（主动提醒）+ 成长性（越用越懂）。三者叠加形成用户离不开的"记忆黑盒"。

## 3. MVP 范围

### 3.1 核心功能（三大有限要点）

| # | 功能 | 价值 |
|---|---|---|
| 1 | **语音记忆**：对着应用说话（BT 耳机或麦克风），自动转写、抽取、入库 | 记忆底座，FOMO 依赖 |
| 2 | **承诺提醒**：对话中"周三交方案"自动提取为待办，到时桌面通知 | 每日高频触达，怕忘事 |
| 3 | **回忆查询**：自然语言提问"上次和 XX 聊的方案是啥"，秒回并附原文引用 | 记忆检索，差异化 |

### 3.2 明确非目标（二期/三期）

- ❌ 习惯学习与前瞻规划（需数据积累，二期）
- ❌ 手机端（二期）
- ❌ 每日回顾/晨间报告（二期）
- ❌ 多用户与云同步（三期）
- ❌ 自研硬件吊坠（三期）
- ❌ 通讯录/位置/短信等敏感权限采集（MVP 刻意回避）

## 4. 系统架构

```
┌───────────────────── 客户端（桌面版，Tauri） ─────────────────────┐
│  录音（麦克风/BT耳机） → 本地 Whisper 转写 → 结构化抽取（DeepSeek API） │
│  记忆库（SQLite + FTS5 全文检索）  ←→  查询/提醒引擎                  │
│  通知（承诺到期提醒）   UI（录音/历史/查询/人脉）                      │
└──────────────────────────────────────────────────────────────────┘
                         ▲ 仅发送转写文本
                         │
                  DeepSeek API（抽取 + 问答）
```

### 4.1 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 客户端框架 | Tauri（Rust + Web 前端） | 轻量、麦克风权限零摩擦、可快速分发安装包、Rust 核心可移植手机端 |
| 语音转写 | faster-whisper（本地，small 中文模型） | 免费、隐私好、离线可用 |
| 存储与检索 | SQLite + FTS5 | 本地优先、零运维、中文全文检索 |
| 结构化抽取 | DeepSeek API（function calling 输出 JSON） | 中文强、成本极低（月成本 <¥20）、无需自建 GPU |
| 回忆问答 | DeepSeek API（RAG：检索候选 + 生成回答） | 同上 |
| 提醒调度 | Rust 侧轻量定时调度 | 到期触发桌面通知 |

### 4.2 为什么桌面版先行

- 麦克风权限零摩擦（无需应用商店审核）
- 本地 Whisper 免费转写，隐私好，无 API 成本
- 可快速直接分发给 3-5 名种子用户（安装包/便携版）
- Rust 核心逻辑后期可移植到手机端，避免重复开发

## 5. 核心数据流

```
说话 → 录音(.wav) → 本地转写(文本)
   → ① 原文 + 时间戳 立即入库（conversations 表）   ← 数据永不丢
   → ② 批量发给 DeepSeek 抽取结构化记忆（JSON）
        ├─ 人脉：{name, 关系, 关联事件}
        ├─ 承诺：{内容, 时间/截止, 相关人} → 写入 reminders → 定时提醒
        ├─ 偏好：{主题, 喜好/习惯}
        └─ 事件：{摘要, 人物, 地点}
   → ③ 记忆条目写入 memories 表（带 conversation_id 引用原文）

查询（自然语言）→ 检索候选（FTS5 同时检索 conversations 原文表与 memories 结构化表，关键词 + 时间过滤，结构化命中优先）→ DeepSeek 生成回答（附引用）
```

**关键原则**：原文入库先于结构化——即使抽取失败，记忆也不会丢，只是暂时不可结构化检索。

## 6. 记忆模型

四类结构化记忆，统一 `memories` 表，每条含：id、类型、内容摘要、**来源引用**（conversation_id + 时间戳）、创建时间、置信度。

| 类型 | 用途 | 举例 | 存储要点 |
|---|---|---|---|
| **人脉** people | "谁是谁"的社交图谱 | 张伟·供应商·聊过预算 | 同名实体聚合，关联事件 |
| **承诺** reminders | 怕忘事的核心 | "周三交方案" | 到期触发，状态机（待办/完成/已过） |
| **偏好** preferences | 越用越懂你 | 不喜欢香菜/习惯周三健身 | 长期静态，可被"习惯学习"二期消费 |
| **事件** episodes | 生活时间线 | 8/5 和妈妈去体检 | 时间索引，全文可搜 |

**去重策略**：
- 人脉按姓名归一（同音/别名同义化）
- 承诺按"内容 + 时间"去重

## 7. 主动触达机制

MVP 只做一种主动触达：**承诺到期提醒**。

流程：对话中抽到承诺 → 解析时间（今天/明天/下周/X点；解析失败则询问补充）→ 到期当天早晨通知一次，到期前 15 分钟再通知一次 → 触达失败（应用未运行）则启动时补发。

其余触达（见人前情境速览、每日回顾）明确放二期——依赖日历/位置数据，MVP 不做。

## 8. 错误处理与降级

| 失败点 | 降级策略 |
|---|---|
| 转写失败/无声 | 提示"没听清，请再说一次"，不打断录音 |
| 抽取 API 超时/失败 | 原文已入库，结构化重试队列（下次启动补抽） |
| 无网络 | 本地转写照常，抽取暂缓，联网后补抽 |
| 时间解析失败 | 问一句"什么时候要完成？" |
| API 限额 | 队列降频，保证录音入库永不阻塞 |

## 9. 隐私与合规（PIPL）

- **本地优先**：录音、转写文本、记忆全部存本地 SQLite；仅转写文本发送 DeepSeek 做结构化
- **透明告知**：首次使用明示"语音将被转写并发送云端处理"，提供开关
- **用户控制**：一键查看全部记忆、单条删除、一键清空/导出
- 不采集通讯录/位置/短信等敏感权限（MVP 阶段刻意回避）

## 10. 测试与验收

### 10.1 测试策略

- **单元测试**：时间解析器、承诺抽取 schema 校验、FTS5 检索排序、提醒调度状态机
- **集成测试**：录音→转写→抽取→入库→查询 全链路冒烟（用预录音频，不依赖真人录音）

### 10.2 验收标准

- 种子用户 2-4 周使用，每周 ≥3 次主动打开
- 埋点记录：录音次数 / 查询次数 / 提醒点击率
- 全链路功能稳定，无数据丢失

### 10.3 迭代节奏（单人）

| 周 | 目标 |
|---|---|
| 第 1 周 | 采集 + 转写 + 原文入库 |
| 第 2 周 | 结构化抽取 + 回忆查询 |
| 第 3 周 | 承诺提取 + 提醒通知 |
| 第 4 周 | 种子用户测试 + 埋点收集 |

## 11. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 中文 FTS5 分词质量不佳 | 引入中文分词（jieba 类），或退化为关键词匹配 + 语义检索（二期） |
| 语音抽取准确率不足 | 结构化置信度字段；用户可编辑/删除记忆条目 |
| 用户不养成"说话"习惯 | 降低交互摩擦（一键录音、快捷键），突出查询/提醒的即时价值 |
| DeepSeek 可用性波动 | 抽象 LLM Provider 层，可切换 Qwen/GLM |
