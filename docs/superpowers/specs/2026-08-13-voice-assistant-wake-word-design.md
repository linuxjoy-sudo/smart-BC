# SmartBC：语音助手唤醒式连续问答 — 设计文档

- 日期：2026-08-13
- 状态：草稿（待用户审阅）
- 定位：将"手动录音→停止"升级为"唤醒词→连续问答"的随时助理式交互

## 1. 背景与目标

### 1.1 现状痛点

当前交互为**手动点击录音 → 手动停止 → 等待转写**：

- 每次提问都要走到电脑前点击两次按钮，无法"随时开口问"
- 不适合提供助理式服务（查记忆/日程、设提醒、问问题）

### 1.2 目标

类似智能音箱的交互闭环：**唤醒词 → 聆听窗口内连续问答 → 超时回到待唤醒**。

### 1.3 已确认决策

| 维度 | 决策 |
|---|---|
| 触发方式 | 唤醒词（默认"小贝小贝"，可配置），应用常驻监听 |
| 回复形式 | **A 起步**：文字 + 桌面通知（TTS 语音回复列为后续阶段） |
| 使用场景 | 随时提问（查记忆/日程/人脉）为主；含主动提醒/播报 |
| 对话形态 | **聆听窗口**：唤醒后 30s 内连续多轮问答，超时自动回到待唤醒 |
| 唤醒检测技术 | **方案 1 分层检测**：能量 VAD → whisper 短转写 → 关键词匹配 |
| 隐私 | 默认关闭，设置页显式开启；开启时有状态提示 |

## 2. 交互设计

```
用户：小贝小贝
应用：〈唤醒成功，进入聆听窗口 30s〉
用户：明天几点开会
应用：〈桌面通知〉"根据你的日程，明天上午 10 点有项目评审会。"
用户：帮我记一下，周三交方案给张伟
应用：〈桌面通知〉"已记录：周三交方案给张伟。"
    ...（窗口内可继续，每次答完重置窗口）...
    （30s 无有效语音 → 回到待唤醒，不打扰）
```

### 2.1 主动提醒/播报

复用现有 scheduler 到点提醒（`tauri_plugin_notification`），语音助手开关不影响提醒功能；后续阶段可加 TTS 播报。

## 3. 架构与模块

新增 `src-tauri/src/voice/` 模块，沿用现有 `audio/`、`asr/` 分层，四个独立单元：

| 模块 | 职责 | 依赖 | 可单测性 |
|---|---|---|---|
| `voice/listener.rs` | 常驻 cpal 采集线程 + 帧级能量 VAD + 环形缓冲（约 5s） | cpal、`audio/wav` | 能量阈值判定（合成样本） |
| `voice/wake.rs` | 唤醒词检测：缓冲片段 whisper 短转写 → 匹配 `wake_word` | `asr/whisper` | 文本匹配纯函数 |
| `voice/vad.rs` | 断句判定：静音段 > 1.5s → 句末 | 无 | 纯函数，边界测试 |
| `voice/dialog.rs` | 会话状态机 + 工作线程：编排监听→唤醒→断句→问答→通知 | listener/wake/vad、`query`、notification | 事件序列驱动状态机 |

### 3.1 数据流

```
[cpal 常驻采集] → [能量VAD] ──语音活动──> [环形缓冲≤5s] → [whisper短转写] → 匹配唤醒词?
                                                                  │ 命中
[IDLE] ◄──窗口超时/静音超时── [ACTIVE(30s窗口)] ◄────────────────────┘
                                  │ VAD句末
                                  ▼
                         [整句转写 small] → [RAG问答 query_memories] → [桌面通知]
                                  ▲                                        │
                                  └────────── 窗口重置，继续聆听 ───────────┘
```

## 4. 会话状态机

```
IDLE
  └─ 检测到语音 → 缓冲 → whisper 短转写
       ├─ 含唤醒词 → ACTIVE（启动 30s 窗口）
       └─ 不含 → 清缓冲，回 IDLE

ACTIVE
  ├─ VAD 句末 → PROCESSING（转写/问答）
  ├─ 窗口 30s 超时 → IDLE
  └─ 长时间静音（>10s）→ IDLE

PROCESSING
  ├─ 成功 → 通知结果 → ACTIVE（重置窗口）
  └─ 失败 → 通知错误 → ACTIVE（重置窗口）
```

## 5. 配置项（`config.rs` 扩展）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `voice_assistant_enabled` | bool | `false` | 常驻监听总开关（隐私） |
| `wake_word` | String | `"小贝小贝"` | 唤醒词，设置页可改 |
| `listen_window_secs` | u32 | `30` | 唤醒后聆听窗口时长 |
| `wake_model` | String | `""`（空=复用 small） | 预留：唤醒检测专用模型（base/tiny），MVP 不启用 |

## 6. 麦克风互斥与隐私

- **互斥**：`start_recording`（手动录音）与常驻监听不能同时占用 cpal 设备。全局 `mic_busy` 标志：手动录音开始时暂停监听、结束时恢复；反之监听激活时手动录音入口提示"语音助手监听中"。
- **隐私**：`voice_assistant_enabled` 默认关闭；开启时设置页显示"监听中"状态；应用退出即停止监听。

## 7. 错误处理

| 场景 | 行为 |
|---|---|
| 麦克风被占/不可用 | 通知"语音助手不可用"，回 IDLE |
| 唤醒片段转写失败 | 丢弃，继续监听（不误报） |
| 唤醒词匹配在噪音片段上 | 能量 VAD 阈值过滤低能量片段，降低误唤醒 |
| LLM/问答失败 | 通知"查询失败：{原因}"，回 ACTIVE |
| 窗口内静音超时 | 优雅回 IDLE（不产生假唤醒） |

## 8. 测试计划

| 测试 | 覆盖 |
|---|---|
| `vad.rs` 单元测试 | 静音/语音/句末边界、阈值敏感度 |
| `wake.rs` 测试 | 文本匹配：含唤醒词/不含/首尾空格/换行变体 |
| `dialog.rs` 状态机测试 | 注入事件序列：唤醒命中、未命中、窗口超时、处理失败回退 |
| `listener.rs` 测试 | 合成样本能量判定、缓冲窗口滚动 |
| 集成 | `voice_assistant_enabled` 配置往返；麦克风互斥标志（手动录音↔监听） |

## 9. 明确假设与后续阶段

### 9.1 本次明确假设（可调整）

- 唤醒延迟约 1-2s（复用 small 模型短转写），可接受
- 唤醒词默认"小贝小贝"，可在设置修改
- 回复仅文字+通知，不做 TTS
- 主动提醒沿用现有通知机制，不新增播报

### 9.2 后续阶段（不在本次范围）

1. TTS 语音回复（本地 edge-tts 或系统 TTS）
2. 唤醒检测专用小模型（降低延迟与 CPU）
3. 提醒到点语音播报
4. 手机端联动
